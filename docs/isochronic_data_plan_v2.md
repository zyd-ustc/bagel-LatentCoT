# 数据构建（第二版）：主动编辑为主，修复为辅

日期：2026-11-09 22:00。**取代** [数据底座构建方案](isochronic_data_build_plan.md) §8–§10 的失败挖掘路线。
保留其中的底座盘点（§0）、几何与归一化工程（§1）与 L 线基本做法。

## 0. 为什么要改

第一版把编辑器训练挂在了"底座必须先画错"这个前提上：

```
提示词 → 底座生成 → UND 判定它错了 → UND 写出可验证的修复题 → 才有资格训练编辑器
```

后三个环节同时限制样本数量和编辑类型。分族转化率（colour 43% → text 0%）说明的**不是底座失败率**，
而是这条采样与验收链的产出率。按它训练，编辑器学到的是"底座在颜色绑定上的弱项"，
而不是"按指令改变生成中间态"。

**编辑器不需要知道源图是不是错的，它只需要知道要改什么。**

## 1. 生产合同（主动编辑）

```text
1. 原生 T2I 生成父轨迹：保存真实中间态 a、预览 P、完稿 x_src
2. 看着 x_src 的实际内容，指定一项清晰的编辑 e：
   增 / 删 / 移动 / 位置关系 / 属性（含颜色、材质）
3. 生成与 e 对应的高质量目标图，并验收"编辑完成 + 无关内容保留"
4. 学生只读部署时可得的信息：a、P、e、c_tail
5. 用学生接续后的终图训练，不要求学生回归人为构造的目标状态
```

与第一版的唯一区别：**第 2 步不再经过"诊断认为原图错了"这一关。** 直接用本地化编辑给真实轨迹派任务。

离线用完稿确定编辑任务是合理的——完稿帮助制作准确标签，但**不进入学生输入**。
训练指令采用部署时的短编辑格式。

## 2. 目标图与终端监督

沿用已验证的终端监督：

$$\hat x = F^{c_{\mathrm{tail}}}\big(E_\theta(a, P, e)\big)$$

让接续结果完成目标编辑并保留无关内容。目标图可以直接来自外部强编辑器，
**不再反演成 `b`**——否则又会回到"为了得到状态标签，先要求冻结尾段精确复现外部图片"。
已有的线性编辑对继续承担状态流匹配训练。

## 3. 条件语义必须统一用于数据与推理

| 任务 | `c_tail` | 编辑指令的作用 |
|---|---|---|
| **主动编辑** | 编辑后的完整场景描述 | 完成指定改变 |
| **修复原请求** | **`c_raw`**（原提示词不变） | 纠正实际偏差 |

两者不能混用。当前 `terminal_repair.json` 的配比表要按此重新标注。

## 4. 训练配比（起始安排）

| 数据 | 比例 | 作用 |
|---|---:|---|
| **真实历史态上的主动编辑** | **50%** | 实际中间态上的增删、移动、关系、属性改变 |
| 已有高质量线性编辑对 | 30% | 广泛编辑能力，保住 Stage 1 优势 |
| 已验收的真实失败修复 | 10% | 对接自纠偏用途 |
| 真实保持样本 | 10% | 不需要编辑时保持状态与成图 |

**主动编辑按操作类型分配，不按当前转化率分配。** 颜色不能因为容易生产就挤掉删除、计数与位置关系。

操作配额（每轮）：`remove 30% · count 20% · move 20% · relation 15% · attribute 15%`

## 5. 诊断器：单独处理，用冻结模型

诊断器要解决的不是"预览看起来是否完整"，而是：
**结合原始要求与预览，哪些问题值得干预，哪些应让原生尾段继续完成？**

所以那些「预览看着失败、完稿其实满足要求」的样本**不是废数据**——它们正是教诊断器停止误报的负例，
不该被强行转成修复样本。已产生的 2,086 条验收通过的修复数据保留，作为修复分支的种子。

**执行顺序：先把编辑器训练充分，诊断器暂时用冻结模型。**
不要让编辑器同时承担"判断指令是不是误报"和"执行指令"两件互相冲突的事。

## 6. 生产流程（新）

### 6.1 复用已有资产

| 资产 | 现状 | 用途 |
|---|---|---|
| `targeted/parent`（2,968 条真实轨迹） | 已有 `a`、`P`、`x_src` | **直接派编辑任务**，不必重新生成 |
| `targeted/r1/r2/parent`（10,519 条） | 已有 | 同上 |
| L 编辑对 49 万条 | 已有 | 30% 回放 |
| 修复数据 2,086 条 | 已有 | 10% 修复分支 |
| 真实保持样本 6,576 条 | 已有 | 10% |

**这意味着主动编辑数据不需要重新跑父轨迹**——13,000 余条真实轨迹已经带 `a`、`P`、`x_src`。

### 6.2 每轮生产

```text
已有父轨迹（a, P, x_src）
  → 看 x_src 指定一项本地化编辑 e（按 6.1 的操作配额）
  → 教师按 (P, e) 生成目标 b，尾段得 x_eff
  → 验收：编辑完成 + 无关内容保留 + 画质
  → 入池：R_active
```

只有 6.2 的第 2–4 步需要算力，比第一版少一整段（不再需要为"找错"重复生成）。

## 7. 实施顺序

1. 编写 `propose_active_edit()`：看 `x_src` 按配额选操作类型，产出 `e`、`c_tail`、两组问题
2. 复用 `prepare_coupled --teacher-prompt instruction` 生成 `b` 与 `x_eff`
3. 验收沿用两组问题规则（不存在修复题的"必须为假"要求，改为**编辑题在 x_src 上须为假**——主动编辑同样要保证"确实有改变"）
4. 配方 `terminal_active.json`：active 50% / L 30% / repair 10% / keep 10%
5. 先跑 150 步看编辑完成率与保持，再决定扩量

## 8. 已知限制

- 修复分支的 2,086 条来自"底座失败 + UND 判错"的采样，分布偏颜色绑定，**只能作为 10% 的用途**，不能代表自纠偏能力
- 诊断器尚未训练，闭环里目前用冻结模型，误报率未知
- 主动编辑的目标图由图像条件教师产生，画质基线是 1.9 倍粗糙（见终端监督文档），靠保持项与高频带约束
