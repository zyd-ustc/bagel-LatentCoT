# BAGEL GenEval++ 显式闭环上界：结果（2026-10-23）

无训练，冻结 BAGEL。协议见 [upper_bound_closed_loop_20261023.md](upper_bound_closed_loop_20261023.md)。

## 设置

- 清单：官方 `geneval_pp.jsonl`，280 条；10 shard × 28 条，单卡。
- 原生采样 50 步（CFG 4、shift 3、512px）；`rollback_index=20`（t≈0.813），`read_indexes=25/30/35`（t≈0.742/0.655/0.545）。
- 原子问题：计数/排除用验证式 `Are there exactly N <class>?`，颜色/位置/region 用 Yes/No；判分与检出同用原生 ViT-UND。
- 三个干预臂：
  - `loop`：回退到 t_early，拼上失败约束重走 29 步；
  - `partial`：回退到同一状态、换 seed 重新加噪后重走 29 步（原“等算力对照”）；
  - `full`：全新 50 步、换 seed 的完整重采（补充实验，154 条 base 失败样本补跑）。

base 整图通过 **126/280 = 45.0%**；原子正确率：count 71.0%（631 个）、attribute/position 91.8%（390 个）。

## 结论

1. **预览检出成立。** 召回 84–94%，越晚的 t_read 误报越少（precision 0.59 → 0.83）。代价是早期预览大量误触发。
2. **文字纠正基本无效。** 回退到 t_early 后拼接约束，整图修复率 0–1.5%，count 原子 1–2%，比“什么都不改、只重抽一次”低一个数量级。
3. **“重采修一半”的前提成立。** 完整 50 步重采把 count 失败原子修好约 50%，整图失败修好约 28%。
4. **错误在轨迹早期就基本锁定。** 在同一 t_early 状态上换 seed 重新加噪（partial）只修好 2–4%（count 6–9%），而从头重采修好 28%（count 50%）。说明 t_early 的干净估计已经携带了错误语义，重加噪无法把它洗掉；只有从 t=0 重新开始才能逃逸。
5. **显式闭环输给重采。** 即使 loop 的 retry 只花 29 步、重采花 50 步，loop 仍以约 2% 对约 50%（原子）落后。按既定判据，隐式版本没有可追的上界；同时也说明“在 t_early 打补丁”这个干预位置本身选得太晚。

## 口径与限制

- 判分与检出共用 BAGEL UND，属于自洽口径；27B 独立评分后端未恢复。换判分只影响绝对数，不改变 loop 与 full 的量级差。
- GenEval++ 计数用 VQA 代理，不与官方检测器分数等同；类别名沿用清单原文（“one skis”这类语法不完美，模型仍能正确回答）。
- 单 seed、280 条；置信区间只在配对子集上给 McNemar。
- `partial` 不是“从头换 seed 重采”，而是“同一中间状态换噪声”，用于区分“重加噪”和“重来”两种干预；真正的重采基线是 `full`。

## SenseNova U1.5 · 同协议全量（280 条，12 shard）

- 模型：`/data/zyd_workspace/models/SenseNova-U1.5-8B-MoT`；像素空间采样，`t` 0（噪声）→ 1（干净）。
- `rollback_index=25`（t≈0.25），`read_indexes=35/40/45`（t≈0.438/0.571/0.750）；loop 重试 25 步，full 50 步。
- 判分：原生 VLM chat，`max_answer_tokens=192`，截取 `…` 之后；同一套验证式原子问题。

base 整图通过 **177/280 = 63.2%**。

**检出**：

| t_read | TP/FP/FN | precision | recall |
|---|---|---:|---:|
| 0.438 | 101/154/2 | 0.396 | 0.981 |
| 0.571 | 93/97/10 | 0.489 | 0.903 |
| 0.750 | 82/31/21 | 0.726 | 0.796 |

**修复率（整图）**：

| t_read | n | loop | partial | full |
|---|---:|---:|---:|---:|
| 0.438 | 101 | 15.8% | 12.9% | **35.6%** |
| 0.571 | 93 | 11.8% | 14.0% | **35.5%** |
| 0.750 | 82 | 9.8% | 12.2% | **34.1%** |

**原子级（t=0.438）**：count 失败原子 loop 16.7% / partial 21.6% / full **52.0%**；attribute loop 38.5% / partial 19.2% / full **50.0%**。

## 两模型并列

| | BAGEL（t=0.742） | U1.5（t=0.438） |
|---|---:|---:|
| base 整图通过 | 45.0% | 63.2% |
| loop（整图） | 1.4% | 15.8% |
| partial（整图） | 3.4% | 12.9% |
| full（整图） | **29.0%** | **35.6%** |
| count 原子 loop / full | 2.3% / **52.9%** | 16.7% / **52.0%** |
| attribute 原子 loop / full | 3.1% / **65.6%** | 38.5% / **50.0%** |

**共同结论**：

1. 两个模型的完整重采都把 count 失败原子修好约 **50%**，与“随机重采修一半”的假设一致。
2. 显式 loop 在两个模型上都输给完整重采：BAGEL 差 20 倍（整图），U1.5 差 2–3.5 倍；count 原子差 3–23 倍。
3. U1.5 对晚期文字约束更敏感（loop 10–16% vs BAGEL 0–1.5%），但最多只拿到重采收益的三分之一。
4. 在同一中间状态重新加噪（partial）不足以恢复：BAGEL 只能拿到 full 的 12%，U1.5 约 37%。错误在轨迹中段已被部分锁定，越晚干预收益越小。
5. 按既定判据，显式闭环没有赢过重采，隐式版本没有可追的上界；若要继续，干预点应前移到 prompt/结构阶段，而不是采样中段回退。
