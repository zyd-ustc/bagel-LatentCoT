# 终端图像监督：下一轮大规模训练安排

日期：2026-11-08。前置证据见 [进度记录](isochronic_progress.md) §3.3 与 [标签实验](isochronic_label_experiments.md) §4b。

本文只回答一个问题：**在已经量出标签纹理代价、并且确认接口与读取点都不是原因之后，下一轮训练怎么排。** 它不重复方法叙述，只写决定、数字、门禁和失败回退。

## 1. 从证据直接得到的三条约束

| 证据 | 数值 | 对训练的含义 |
|---|---|---|
| 教师自己的采样就带 2 倍纹理（教师跑完 t=1 与交接后几乎相同） | 教师 1.74–3.65 / 交接 1.63–3.65 | **标签图只能当"改哪里、改成什么"，不能当"该有多干净"** |
| 同条件 text 臂：0.95；换条件 it2i 臂：1.70（同一 48 条请求配对） | 1.70 vs 0.95，44/48 更糙 | 复制这条路径的标签、复制它的纹理；标签的干净程度由采样条件决定 |
| 读取点无影响、尾段细分 2× 更糙 | 0.910/0.910/0.914；1.194/1.200/1.202 | 这两个旋钮不要再动 |

由此确定训练目标必须**分工**：

- **结构/语义**由标签图给（它是对的，只是糙）；
- **画质**由父图自己的原生完稿给（它是干净的，只是没有这次编辑）；
- 两者用同一张掩码分开，并且**显式给高频定一个预算**。

也就是说：监督最终图，但不要把"最终图"当成一张要逐像素模仿的图。

## 2. 目标函数

学生从 `a` 出发，8 步等时编辑得到 `b̂`，再用**部署完全相同的尾段**接续：

```
b̂  = Edit(a, t=0.36, s: 0→1, P, e, c_tail)          # 8 步，grad 打开
x̂  = Φ^{c_tail}_{1←t}(b̂)                            # 19 步 Euler，CFG=4，grad 打开
```

损失四项：

```
L_struct   = mean_{M}       |x̂ − x_teacher|_1
L_preserve = mean_{1−M}     |x̂ − x_src|_1
L_hf       = ( hf(x̂) − hf(x_src) )²                  # hf = mean|Laplacian|
L          = L_struct + λ_p·L_preserve + λ_hf·L_hf
```

默认 `λ_p = 1.0`，`λ_hf = 5.0`（量纲对齐：hf 在 0.05 量级，L1 在 0.1 量级；首 25 步看梯度范数再定）。

**掩码**：`M = clip((|x_teacher − x_src| − q60)/(q95 − q60), 0, 1)`，再 3×3 均值模糊一次。软掩码，不用硬阈值——教师保留场景，差异本来就集中在编辑处；硬阈值会把边缘判错。

**为什么不是 L2**：L2 在图像空间同样奖励高频（这也是状态 L2 出事的原因）。L1 + hf 预算把"变糙"从"免费"改成"付费"。

**不加 LPIPS 损失**：编辑区里的标签是糙的，用感知损失去贴它等于把粗糙当目标。LPIPS 只留在评测端。

## 3. 三类数据的角色

| 角色 | 占比 | 来源 | 目标图 | 掩码 |
|---|---:|---|---|---|
| R-edit | 55% | v5 it2i 路线（教师读父图原生完稿）扩到 ~620 条 | `x_teacher` | `\|x_teacher − x_src\|` |
| R-keep | 30% | 现有 6576 条 | `x_src`（同一轨迹原生完稿） | 空 → 只剩 `L_preserve + L_hf` |
| L-edit | 15% | 现有 28849 线性对 | `x_target` | `\|x_target − x_source\|` |

**R-keep 在新目标下自动变成正确形式。** 以前是 `b = a` 的形式约束（模型可以用加高频买"看起来没变"），现在是"你的输出必须等于这条轨迹自己的原生完稿"，加高频会直接被 `L_hf` 收钱。这条应该能直接把 0.99 → 1.77 的回归修回去，也是最便宜的一次自证。

**R-edit 数据量**：v5 协议 224/400 请求通过（78%）。要到 ~620 条需 ~800 请求，8 卡约 1.5 小时。这是本轮唯一需要新增的生产。

**仍然不用**：I 数据、反演、外部编辑器目标。

## 5. 训练配置

| 项 | 值 | 理由 |
|---|---|---|
| 初始化 | `stage1_30k/step_003607` | 它的输出高频 0.99、画质与原生持平；`stage2` 权重已经编码了"买高频"的解，从干净起点出发更省 |
| `t` | 0.36 | 读取点已证明不影响标签图，保持单点 |
| 编辑步数 | 8 | 不变 |
| 尾段细分 | 1× | 2× 实测更糙 |
| CFG | 4（尾段） | 必须与部署一致 |
| lr | 5e-6 → 1e-6 cosine，warmup 50 | 梯度穿过 CFG=4 的尾段被放大约 4 倍，比上一轮的 1e-5 再降一档 |
| clip | 1.0 | 不变 |
| 更新数 | 400 | 见曝光核算 |
| 保存 | 每 50 步 | 行为可能随步数变差，需要细粒度检查点 |

**曝光核算**：400 × 64 = 25,600；R-edit 25,600 × 0.55 / 620 ≈ **22.7 次/条**（≤25 ✓）。

要跑到 800 步就必须先把 R-edit 扩到 ~1300 条，否则单条曝光翻倍、退化成背样本。

## 6. 门禁（必须进代码，不再用人工待审代替）

每 50 步，固定 32 例留出集（R-edit 16 + R-keep 16），报四项：

| 指标 | 门禁 | 说明 |
|---|---|---|
| `hf(x̂)/hf(x_src)` 中位 | **≤ 1.30**，硬失败 >1.5 | 这就是本轮要压的东西 |
| `edit_complete` 率 | ≥ 标签自身（78%）− 5 点 | 不许用画质换语义 |
| R-keep 的 `hf` 比 | ≤ 1.10 | 保持任务必须干净 |
| R-keep 的 LPIPS(vs 同轨迹原生终图) | ≤ 0.1574 | 上一轮 `stage2/500` 的基线 |

训练日志每 10 步记一次 `hf(x̂)`（单样本，成本可忽略）。**若 hf 上升而 edit_complete 不动，立即停**——那是目标被空空间吃掉的标准签名。

## 7. 执行顺序

### 第 0 步：单例过拟合（1 卡，约 40 分钟，今晚就能跑）

16 条 R-edit，只优化 §2 的损失，不评测、不保存发布权重。看三件事：

1. 损失能否稳定下降；
2. `edit_questions` 在 `x̂` 上是否全过；
3. `hf(x̂)/hf(x_src)` 是否压到 1.1 以内。

**判据**：三条同时成立才值得上 64 卡。若 1 降而 2 不升 → 空空间吃掉目标，回到损失加约束（提高 `λ_p`、加 `L_state` 锚）。若 1 降 2 升而 3 压不住 → `λ_hf` 太弱或掩码判错，先修这两处再谈规模。

### 第 1 步：标签扩容（8 卡，约 1.5 小时）

v5 协议扩到 800 请求，取 ~620 条通过。与训练入口改造并行。

### 第 2 步：核心 A/B（64 卡，2 × 100 步，约 1 小时）

同一份数据、同一个初始化，只差损失：

- **A（旧）**：`((u_θ − (b−a))/t)²`，即当前配方；
- **B（新）**：§2 的终端损失。

这是全轮唯一必须回答的问题：**换目标有没有用。** 判 B 的 `hf` 比 A 低、`edit_complete` 不低于 A。

### 第 3 步：主跑 + 三条消融（64 卡，400 步 + 3 × 100 步）

主跑 B；消融各 100 步：

- C：`λ_p = 0` → 验证空空间风险是真的还是想象的；
- D：加 `L_state = ||b̂ − b*||²`（λ=0.05）→ 验证"贴标签状态"是不是只在买更多高频；
- E：从 `stage2/500` 初始化 → 验证坏习惯能不能洗掉。

### 第 4 步：出图判定

32 例 + 64 例闭环，出三列对照（x_src / x_teacher / x̂），跑 `audit_xeff_quality.py --gate`，人工只看四栏：编辑完成 / 新增形体缺陷 / 纹理退化 / 误改。

## 8. 接口变化与实现面

只有两处需要改，都在控制流层：

1. `field.edit_state` 现在整段包在 `torch.no_grad()` 里，需要开一档 `grad=True`；
2. `train.py` 增加终端分支：`euler(b̂, segment_times(grid, t, 1.0), NativeT2I(rt, c_tail, cfg))`，**不经过** `forward_native`（那个带 `no_grad`）。

`euler` 已在每步用 `checkpoint`，`rt.predict` 本来就没有 `no_grad`，所以尾段可以直接反传，不需要新模型代码。掩码与 `L_hf` 是纯张量运算。

## 9. 失败回退

| 现象 | 处置 |
|---|---|
| 梯度爆 / 损失振荡 | 尾段只反传前 K=6 步、后段 detach；lr 再降一档；clip 0.5 |
| `hf` 压不住但语义在涨 | 提高 `λ_hf` 到 10；或把 `L_hf` 改成对编辑区加权 |
| 语义塌（改不动） | 提高 R-edit 占比到 0.7；或允许 `L_state` 锚（牺牲一点画质换位移幅度） |
| 掩码把无关区域圈进去 | 掩码阈值从 q60 提到 q75，并用 UND 的 `preserve_questions` 反查误圈位置 |
| 全部指标都好但图难看 | 说明 `hf` 不足以表征画质，改用 LPIPS 到同轨迹原生终图 + 分区域 hf，并把这个发现写进 §3.3 |
| L-edit 批次的 `hf` 明显高于 R 批次 | 线性对的 `b` 不在 `c_tail` 轨迹上，会把离流形状态重新引进来；把 L 占比从 0.15 降到 0.05 或直接去掉，用 R-keep 兜住"不遗忘" |

## 10. 与教师 CFG 扫描的关系

正在跑的教师 CFG 扫描（1/2/4）是**上游红利**，不是本方案的前提：

- 若 CFG=1 或 2 让标签回到 1.2–1.4 且 `edit_complete` 不塌：重产标签，`λ_hf` 降到 1.0，本方案照跑，收敛更快；
- 若 CFG 拉低后编辑做不完：标签维持现状，`λ_hf` 是主力，本方案不变。

**两条分支都不改训练安排**，唯一区别是 `λ_hf` 的初值和标签要不要重产。所以不必等扫描结果再启动第 0 步。

### 11.1 单例过拟合的实际结论（01:31）

训练日志里的均值不能判学习：每条样本的编辑区大小、标签距离都不同，跨步均值不可比，所以第一版门禁两次误判"没学到"。改用**固定 8 例探针**（`scripts/probe_terminal.py`，同缓存、同 t、无采样）对照：

| 探针 | structure | preserve | hf_ratio |
|---|---:|---:|---:|
| 初始化（LoRA 零） | 0.4899 | 0.0377 | 1.037 |
| `terminal_overfit/step_000120`（lr 2e-5，120 步） | **0.3745**（−23.6%） | 0.0569（+51%） | **1.025** |
| 标签图自身（上限参照） | 0.0 | — | **1.904** |

三件事：

1. **目标可学**：固定样本上结构项下降 23.6%，损失 0.530→0.434。单卡 300 步内有效。
2. **画质没有被牺牲**：学生输出的高频比 1.02，而它模仿的标签是 1.90。两侧损失确实把"改对"和"变糙"分开了，这是本轮方案的核心假设第一次被数据支持。
3. **代价在保持项**：0.038→0.057。绝对值小，但方向正确——编辑区变大了，保持区被压缩。主跑里要靠 keep 数据和 `preserve_weight` 盯住。

由此把门禁从"训练损失均值"改成"固定探针 + 与初始化对比"：`structure ≤ 0.85 × init` 且 `hf_ratio ≤ 1.30`。流水线于 02:18 以新门禁重启，从标签扩容阶段继续。

### 11.4 受控玩具实验（08:45，CPU，`scripts/toy_terminal_demo.py`）

集群失联期间用一个 24×24 的条件流模型复现同一结构（同一噪声、两个条件各走一条轨迹，编辑器把 `a` 搬到 `b`），用来检验"状态回归会买高频"这个说法。结论是**它不成立**，而且这个否定有用：

| 目标 | hf 比 | 编辑 L1 | 保持 L1 |
|---|---:|---:|---:|
| 状态回归 | 1.124 | **0.0052** | 0.0136 |
| 终端（无高频带） | 1.192 | **0.0042** | 0.0144 |
| 终端（高频带权重 1.0） | **0.266** | 0.1502 | 0.1463 |

1. **配对自洽时，状态回归没有问题。** 玩具里 `b*` 是同一条件场自己走出来的状态，尾段接它必然回到目标图，所以拟合状态就等于完成任务（编辑 L1 0.005），高频也没有升高（1.12）。所以"状态 L2 天生奖励高频"是错的写法。
2. **真实系统的问题因此被定位得更准**：不是损失形式错了，而是**标签状态不在尾段所走的那条轨迹上**。这与实测一致——同条件 0.95、换条件 1.85、求逆 3.12。终端目标的真正价值只在后两种不自洽的配对里。
3. **高频带权重过大会把图糊掉**（hf 0.27、编辑 L1 0.15）。这是个有效的反面警告：`frequency_weight` 不能主导损失。真实训练里探针给出的 1.025 说明当前 0.5 没有过冲。

一次诚实的限定：玩具没有复现真实系统的粗糙，所以它**不能**当作"终端目标更优"的证据；它能证明的只有第 1 条（状态回归在自洽配对下是合理的）和第 2 条（因此问题被定位到配对不自洽）。

## 12. 审查后的更正（2026-11-09 下午）

一份独立审查核对了远端实际运行版本，指出三处口径错误、两处工程缺陷和一处机制归因错误。逐条复核后**全部成立**，本节按"原表述 → 更正"记录，§11.4 与 §11.7 的相应结论以本节为准。

### 12.1 机制归因：错的

| 原表述（§11.4、§11.7） | 更正 |
|---|---|
| "问题不是损失形式，而是标签状态不在尾段所走的那条轨迹上" | **在 `coupled_v6` 上不成立。** `coupled.py` 里 `effective = euler(b, …)`，记录里的 `target_image` 就是 `{uid}_effective.png`，所以标签图本来就是 `Φ^{c_tail}_{1←t}(b)`。标签状态与标签图天然接续对应。 |

正确的机制是：**状态回归在模仿一个"其自身接续就是粗糙教师图"的状态**（这批标签的 hf 中位 1.9），所以学得越像，越会复制那份粗糙。终端监督给了学生偏离 `b` 的余地——保持项锚在干净的父图、高频带压住纹理——于是它找到了一张比标签更干净的图。

这仍然是有价值的结果，但它说明的是"**可以改善教师目标隐含的质量取舍**"，不是"状态回归必然制造高频"。

同理，先前用"1.777 与第二轮 1.77 数字接近"论证机制，属于跨数据、跨口径的数字比附，不构成证据，撤回。

### 12.2 A/B 不是严格对照

| 项 | 事实 | 处置 |
|---|---|---|
| 学习率 | A `5e-6`，B `2e-5`——我给 overfit 调高 lr 后没有为 A/B 复原 | 已加 `terminal_stateloss_2e5.json`（lr 2e-5），A2 已排队 |
| "初始化"基线 | `probe_init.json` **没有加载检查点**，测的是零适配器；而 A/B 都从 `step_003607` 起步 | 已排队 `probe_base`（`--checkpoint step_003607`），此后一切都对真基线比 |

| `structure` 的含义 | 是**掩码内像素 L1**，不是计数/位置/编辑完成率 | 不能写成"编辑正确性持平" |

### 12.3 已修的工程缺陷

1. **第三条消融被静默跳过**：驱动里写的 `isochronic_data_20261106/runs/stage2_36/step_000500` 不存在，真实路径在 `…20261107/runs/…`。已改。

## 13. 结果定位与下一阶段主问题（2026-11-09 15:30）

训练未中断，本节只记录判断与文档更新。

### 13.1 这批图册究竟展示了什么

它是**文生图中间态上的显式编辑任务**，不是完整的 T2I 自动纠错评测。链路是：

```text
原提示词 → 原生 T2I 生成至 t=0.36 → 保存 a、取预览 P
        → 给定编辑指令 e（如"加一盆植物"）
        → 学生修改 a → 原生尾段续生到 t=1
```

学生实际接收 `(a, P, e, c_tail)`。两张"源图"要分清：

| 图像 | 用途 | 学生推理时可见 |
|---|---|---|
| 中途预览 `P` | UND 的图像条件 | **能** |
| 父图原生完稿 `x_src`（图册第 1 列） | 生成教师标签、算保持损失、做对照 | **不能**，不是学生条件 |

这批任务**没有要求模型发现原提示词哪里没画对**——原图本来可以完全正确。

**核对结果：24 例全部是 `Add …`。** 也就是说图册只覆盖一种操作：**利用空白区域新增内容**，不覆盖任何需要撤销已有结构的操作。

### 13.2 与 `step_003607` 的关系

同一能力，不同状态与监督。Stage 1 的标签满足 `b−a = t(x_target − x_source)`，教的是"图像该怎样变化"；当前训练补的是"**在真实历史态上，怎样改才能让后续生成得到好图**"。这是把已有编辑能力适配到真实生成过程，不是第一次学会编辑。

**图册不能证明比 `step_003607` 更强**，因为三列里没有旧检查点的学生输出（教师标签不是旧学生，父图直通也不是）。目前唯一的比较来自固定 8 例探针：

| 探针 | structure | preserve | hf |
|---|---:|---:|---:|
| `step_003607` 基线 | 0.4233 | 0.0556 | 0.996 |
| B 终端（lr 2e-5，8 卡 120 步） | 0.3281（−22.5%） | 0.0614（变差） | 1.122（上升） |
| A2 状态回归（lr 2e-5，64 卡） | 0.2742 | 0.1110 | 1.852 |

能说的是：**更贴近编辑目标；保持与高频有代价，且这笔代价小于旧状态回归。** 不能说的是编辑成功率提高了多少。

> **待办（零新数据）**：在同一批 `(a, P, e, c_tail)` 上补 `step_003607` 的学生输出，把图册改成
> **父图原生完稿 / `step_003607` 编辑输出 / 当前编辑输出** 三列。教师图降为辅助列。

### 13.3 完整闭环还差什么

```text
原提示词 → 生成 → 判断哪里违反原提示词 → 形成修正指令 → 编辑 → 满足原提示词
         ↑ 已跨过：可以把中间态改对且不崩画质
                   ↑ 尚未完成：这个学习任务的转换
```

关键不是"生成途中能调用的编辑器"，而是**看到自己偏离意图，知道该改什么，并在已有画面上修回来**。

**最主要的差距：从"增加内容"变成"推翻错误内容"。** 真实 T2I 失败通常要求重新组织已有结构——六个改成七个、紫色从大象移到袋鼠、左右关系交换、拆开粘连主体、删除多余对象并补全遮挡背景。这些才是"改不动 / 重影 / 融合"的核心困难，而当前 24 例一个都没覆盖。

### 13.4 主问题定稿

> **理解反馈能否指导模型撤销一个具体的错误决定，同时保留与原意图相容的部分？**

不是继续证明能加多少种盆栽，也不是继续压 hf。

**UND 的角色也要随之升级**：从"提供条件"到"决定修改"。同一句原提示词，在不同失败画面上必须产生不同操作：

| 当前画面 | 应有的动作 |
|---|---|
| 六个牛角包 | 增加一个 |
| 八个 | 删除一个 |
| 数量对但一个变红 | 只改颜色 |
| 全部正确 | 不动 |

自纠错任务里 `c_tail` 通常仍是原提示词；反馈增加的是"现在错在哪里、该怎样修"，而不是不断重写更长的场景描述。**这才是 UND–GEN 交互的实质**，比"共享了多少层 KV"更有分量。

### 13.5 当前优化没有完全对准"修复成功"

掩码 L1 + 保持项存在一个廉价解：**改一点、改小一点**。图册已出现该倾向——桌子和杯子出现、书没出现；犁的轮架出现、牛没出现；新增对象偏小；位置附近有变化但没放到指定位置。

所以画质与保持已进入可用区间，**完整执行语义操作正在成为主要瓶颈**。

### 13.6 下一阶段的训练任务（保留现有模型与终端路线）

| 数据 | 职责 |
|---|---|
| **真实错误修复**（新的主任务） | 撤销错误数量、属性绑定、空间关系；重新组织已有内容 |
| 高质量显式编辑对 | 维持能力广度：增删、替换、移动、重建 |
| 无需修改的真实状态 | 学会"反馈不要求行动"时不动作 |

修复数据最重要的不是缓存格式，而是三个对象的对应：**原始意图 → 当前具体错误 → 保内容的正确修改**。目标图展示修改后的作品，中间状态仍由学生自己学出来——不要回到"先求唯一正确状态标签"的旧问题。

### 13.7 论文主张的落点

> **理解专家让生成模型能够根据自身当前的错误，选择并执行不同的状态修改，在一次生成过程中恢复原始意图。**

判据不是"学生是否比教师更干净"，而是：**原提示词不变、错误形式改变时，它能否跟着视觉反馈改变修复行为。**

### 13.9 数据实测：整条 R-edit 训练集几乎全是"添加"

对 `explicit_v6/requests_all.jsonl` 的 423 条请求做分类：

| 类型 | 条数 | 占比 |
|---|---:|---:|
| Add | **416** | **98.3%** |
| 属性修改 | 7 | 1.7% |
| Remove / 计数 / 空间关系 | **0** | 0% |

这不是图册挑样的偏差，是**训练集本身**的构成。也就是说：**模型没有被教过任何一次"撤销已有结构"**，所以图册里看不到这类能力是必然的，不能归因于方法或损失。

根因在请求生成规则：显式编辑要求"这一条编辑题必须在源图上为假"。"Add X"天然为假，"Remove X"要求 X 确实存在、"6→7"要求恰好是 6，构造和验证都难得多。于是生成器系统性地偏向 Add。

**对下一阶段的直接含义**：修复任务缺的不是轨迹缓存格式，是**请求分布**。下一批请求必须按「计数 / 属性绑定 / 空间关系 / 删除」四类显式配额生成，并且每类都要有"错误确实存在"的前置校验，否则会再次退化成 98% 的 Add。
