# E1 补测记录与首轮训练数据准备（历史记录）

日期：2026-11-05。E1 已完成；本记录没有启动新训练、生成或裁判调用。本文属于 `u15_selective_history_editor_v1` 阶段，已被 [等时生成态编辑方案](isochronic_state_flow_training_plan.md) 取代；旧命令与训练配方不再是活动实现。

## 1. 本轮结果与决定

**停止扩大免训练搜索，进入有高质量目标的真实历史态接续训练。** 原生编辑器提供初始化，训练直接学习撤销历史态中的错误结构；不把 E1 的纯噪声结果或历史接续结果作为成功教师。

用户人工查看的结论是：历史接续没有表现出可靠的语义编辑；明显的语义改变主要出现在纯噪声起点，且正确率低。这是本轮定性结论，尚无逐例人工标签，不能写成人工成功率为零。

- 前缀为原生 Euler、读取点 0.36，编辑为完整原生图像条件场直到终点，CFG=4、图像 CFG=1，回退不刷新噪声。

下表是图册中的 GLM 评分，不是人工形体评审结果。触发的 64 例中，原生参照 22 例通过、42 例失败；其余 64 例直通。

原生参照为 71/128。自动分数显示，纯噪声修好更多，也改坏更多；总通过率只净增 1 例。历史臂净增 2 例也不足以说明它具备可靠的结构修复能力。不能只取修复率，忽略破坏和形体。

### 已查看的具体图像

- `00016 / seven green croissants`：原生图为六个；历史接续仍是六个、布局基本不变；纯噪声变成五个。纯噪声改变了结构，但没有完成“七个”的指令。
- `00124 / a croissant, and two stone cats playing with a dog`：历史接续主要改变猫样主体的表面图案，没有可靠地拆开并补足要求的独立主体；纯噪声增加石头质感，仍有猫狗融合。自动原子题通过不能替代这类视觉判断。

本轮支持的机制判断：原生编辑器从真实历史态接续存在明显适配缺口；预览条件下的编辑本身也不够稳定。训练必须同时约束编辑完成和成图质量，而不能继续把“变化更大”当作成功。

## 2. 造数据前必须修正的标签问题

图册仍有实体—属性错绑：

| 记录 | 原要求 | 实际编辑句 |
|---|---|---|
| `00005 / geneval2_0014_s18` | `a toy and a white bagel` | `Make the toy white.` |
| `00006 / geneval2_0015_s17` | `a elephant and a purple kangaroo` | `Make the elephant purple.` |

`00006` 原始拆题甚至包含 `Is the elephant purple?` 和 `Is the kangaroo an elephant?`。过滤原文不存在的词不足以消除这种错误：实体和属性都在原文里，但关系绑定错了。

这会直接制造坏监督。若教师照错误指令改图，学生将学会违背用户要求；若教师照原要求改图，学生输入与目标又互相矛盾。

**先把条件生产改为基于已绑定的要求生成指令，再生产 B 数据。** 使用现有 UND 或 GLM 文本能力即可，不增加网络。每项要求保存 `subject, predicate, value/object` 及其原文依据；图像质检只决定该项是否满足，不重新编造要求。训练和部署使用同一构造器、同一诊断协议。

例如颜色要求应是 `(kangaroo, color, purple)`，不得退化为“图中有 purple 和 elephant，所以可以把 elephant 改紫”。确认无依据的要求直接删除，不给它配编辑目标。此次记录中的错误保留在原始实验中，不事后改标签重算成更好的成绩。

这是一项已发现的代码/标签修复，不是新增实验门槛。修复后仍使用当前图册作为开发材料，不为它再做一轮大规模零训练搜索。

## 3. 首批数据怎么准备

### A：现有高质量编辑对，先选 5,000–10,000 对

直接转换成 `native_edit`，源图、指令、目标图都来自已有数据。首批以数量增减、主体增删、位置移动为主，辅以颜色和材质，覆盖不同主体与场景。按源图家族划分训练和保留集，同一源图的不同编辑不能跨集合。

保留真正执行指令、主体清晰、画面相容的配对。不要因文件属于“高质量数据集”就把视角重写、构图重做或标签残句重新混入。已有可信质量标注可直接使用，不要求重复审核整库。

A 继续使用原生单步流匹配。它提供编辑能力和画质回放，不承担真实历史态对齐；不把源图加噪当成 `a_tau`，也不把清晰源图简单模糊后冒充真实预览。

### B：先做 500 条有目标的真实失败轨迹

建议首批目标数：250 条计数/主体增删，150 条位置关系，100 条颜色/材质。这个配比是围绕当前缺口的生产预算，不是已验证的最优比例。

每条按以下顺序生产：

1. 从独立训练提示词取一个固定种子。不要使用本轮 64 条或旧 200 例评测提示词，也不搜索更容易修复的种子。
2. 用冻结原生 T2I 跑一次真实父轨迹，保存 0.07、0.15、0.25、0.36，生成真实预览。由修正后的部署诊断器产生编辑条件。
3. 离线续完同一轨迹，得到清晰原生终图 `x_fail`。它仅用于生产目标和标注，不进入学生条件。
4. 用强编辑器在 `x_fail` 上执行本轮短指令，每个任务生成一张目标 `x_star`。可以使用 Qwen-Image 或其他已确认可用的强编辑器，不依赖当前免训练接续器。
5. 保留指令已完成、主体完整、非编辑内容合理保持且与预览场景相容的目标。数量必须实际数对；位置移动允许占用新位置，不能用全图相似度把正确移动筛掉。首批 500 张目标逐张人工确认形体。
6. 不合格目标不进入训练，也不从多次采样里选赢家。记录失败原因与类别；缺额由新的独立任务补充，特别困难的类别用人工编辑或更强的单次目标补齐。

500 指的是**验收后的目标数**，不是保证 500 次调用就能得到 500 条。记录实际单次接受率和费用。

优先制作单一明确修复任务，例如“六个绿色牛角包变七个”。同一图若还有材质等问题，只修本轮明确授权的内容；目标不要偷偷把其他问题也修好。多项修复可后续加入，首轮不让复杂目标掩盖指令—目标对应关系。

对于需要移动、增删主体的样本，顺手标一个粗编辑区域，包含原位置、目标位置和必要遮挡范围。已有 `edit_region` 接口可用于平衡编辑区与保留区的 L1，不新增分割网络。没有可信区域标注时使用全图损失。

### C：50–60 条真实保持轨迹

从独立训练提示词取得真实正确父轨迹，指令为保持当前场景，目标是原生终图。它们约占历史展开抽样的 10%。这部分保留当前已有设计，不因结构编辑困难而扩大保持权重，把学生重新训练成不改图。

诊断错误的修改请求不得配“保持原图”目标。先修正条件或排除矛盾记录；已经正确的原生终图也不因为预览触发就自动作为失败编辑源。

### 交付给训练器的内容

```text
corpus.json
  native_edit: source_image, target_image, edit_condition
  history_edit / history_keep:
    trace, tau, target_image, edit_condition
    raw_prompt, parent_branch_id, protocol_version
    semantic_approved, human_quality_approved
  全部记录: uid, split, prompt_family, source_family
traces/*.pt       真实状态、预览、协议、父轨迹记录
targets/*        已验收且使用训练画布的目标
edit_regions/*   可选、可信的粗编辑区域
```

每个源图家族和提示词家族分别隔离 split，不只检查它们的二元组合。教师版本、单次生成指令、接受/拒绝原因另保存在生产记录中；教师指令不代替学生的 `edit_condition`。

## 4. 第一轮如何训练

### 不再安排一个“重新建立编辑能力”的长预训练

从原生权重的零初始化 GEN LoRA 开始；不加载旧残差 Stage 1/2。第一步起就同时学习 A 和 B/C：

- A：原生 FM，继续提供完整编辑能力和画质监督。
- B/C：真实历史态 → 当前编辑器完整积分到 1 → 未裁剪有效区 L1 + 输出图像 LPIPS，全程真实梯度。

保持现有完整编辑 CFG，不改残差，不加早退尾段，不上 RL。E1 的失败输出没有成为标签；即使当前学生从 `a_tau` 修不好，合格的 `x_star` 仍能提供监督。可学习的信号来自强目标，而不是教师恰好修成功的概率。

### 起点与训练量

首轮与当前部署规则对齐：结构修改从 0.07 开始，颜色/材质从 0.15 开始。先不让模型同时承担 0.25/0.36 的更晚结构撤销。晚节点照常记录，等 0.07 能可靠修改结构后再用于下一阶段，避免重做父轨迹。

首轮上限 200 步，学习率 `1e-5`，warmup 20，裁剪阈值 1，`lambda_fm=lambda_perceptual=1`。这是有限训练尝试，不表示 200 步已经收敛。使用普通权重，保持原生 T2I 路径冻结，不改其参数。

当前实现每卡每步一条 A，加一条 B 或 C。如果使用 64 卡，200 步约产生 12,800 次 A 样本曝光，以及 12,800 次历史样本曝光，其中约 11,520 次 B、1,280 次 C。500 条 B 平均约被看到 23 次；应记录实际 UID 曝光，不把重复抽样算成新增训练数据。A/B 各自按全局均值累积梯度后再更新一次。

完整展开的成本明显高于单步 FM。并行规模由实际可用显存和吞吐决定，本记录不承诺 64 卡的完成时间，也不通过粗网格反向降低名义成本。

### 本轮训练的成败信号

复用既有开发提示词，不新增时间扫描。用修正后的同一反馈重新生成原生编辑基线与训练后结果，已有图册作为旧协议结果保留。只在计划检查点查看少量固定图，例如第 50、100、200 步。

主要观察三个问题：

1. 原先“六个始终还是六个”的历史接续，是否真的按指令增减主体？
2. 修改后的主体是否完整，是否出现猫狗融合、表面画出新主体却没有独立结构等问题？
3. 背景、颜色和无需修改的物体是否仍保持？

损失下降但结构仍不动，不能直接决定加到万步；它说明当前目标、损失权重或可优化性还没有转化为能力。结构开始改变且形体保持，才值得扩大数据和步数。现有纯噪声臂继续作为能力参照，不把它的新随机成图当训练目标。

## 5. 当前实现与准备依赖

后续代码更新已修复此前审查中发现的跨卡重复抽样、梯度未按卡数归一化，以及 LPIPS 未按输出范围处理的问题；本记录不把旧发现重复当作当前阻塞。

开始批量 B 生产前，当前负责人需完成实体—属性绑定修复，并给诊断协议一个新的可追溯版本。开始训练前还需落实两项已有合同：

- 数据划分分别以 `prompt_family` 和 `source_family` 为键。目前 `Corpus` 用二元组合判断冲突，同一源图换一个提示词家族仍可跨 split，需要在数据入口修正。
- A 的时间分布与有效区监督按原生回放定义处理。现有配置的 `p_mean=0, p_std=1` 不等于本轮底座记录的 `P_mean=-0.8, P_std=0.8`；应明确采用底座时间分布和对应 schedule，而不是把部署步数网格的设置自动当成预训练配方。当前 FM 对整个画布直接求均值，有补边的编辑对还需按有效区/padding 分别归一化。

它们是已识别的实现合同，不要求另开评测活动。本轮仅记录修正要求，没有修改这些训练代码。

本轮交付：已有 E1 结果及自动汇总已记录；下一步训练和数据配方已明确；尚未生成训练目标、调用外部 API 或启动训练。
