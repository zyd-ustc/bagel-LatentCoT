# 标签构造对比实验总报告

2026-11-08,modelarts-64(4×16 NPU)。本报告汇总本轮为回答一个问题所做的全部对比实验:
**怎样构造 (a, b) 配对,才能让"真实入口 + 明确编辑 + 实际接续成图合格"三者同时成立。**

所有数字来自运行记录(`/data/zyd_workspace/isochronic_data_20261107/`),没有估计值;人工判读部分单独标注。

---

## 0. 名词与记号

| 记号 | 含义 |
|---|---|
| `t` | 原生生成时间,0 噪声、1 图像;本轮固定 `t = 0.36` |
| `ε` | 初始噪声(同一配对的两条轨迹可共享) |
| `a` | 源轨迹在 `t` 的状态,必须来自真实前向 |
| `b` | 目标状态的标签 |
| `P` | 从 `a` 副本前瞻得到的预览(部署可见) |
| `x_src` | 源轨迹自己的终图 `F^{c_parent}_{t→1}(a)` |
| `c_raw` / `c_parent` / `c_tail` | 原提示词 / 父条件 / 编辑后的完整目标条件 |
| **`x_eff`** | **标签参考终图** `F^{c_tail}_{t→1}(b)`,即"学生精确到达 `b` 时会生成的图" |
| `x̂` | 学生实际产出 `F^{c_tail}_{t→1}(b̂)`,训练后评测对象 |
| `hf` | 灰度图拉普拉斯绝对值均值,高频能量代理量(细节与噪声都计入) |
| `Ψ` | 数值反演程序(把图像映射到 `t` 的状态) |

**验收对象的一处关键约定**:语义验收一律在 `x_eff` 上做,不在任何"候选编辑图"上。候选只负责提出一次编辑,不定义尾段会渲染出什么。

## 1. 被判否定的路线:先出候选图,再反演成状态

### 1.1 目的

这是原方案的构造:外部编辑器给候选目标 `x_edit`,反演出 `b = Ψ(x_edit)`,再用冻结尾段接续。要回答的是:**这条链能否给出可训练的 (a, b)**。

### 1.2 配置

`prepare-state-pairs --mode inverted`,`t=0.36`,部署网格 50 步 shift=3 Euler CFG=4,`t_eps=0.05`。

### 1.3 实验 A1:反演往返误差 vs 求解器设置

同 4 对线性配对,反演至 0.36 再正向重建,有效区 L1 / LPIPS-VGG:

| 逆向细分 | 端点取值 | 源侧 | 目标侧 |
|---:|---|---|---|
| 1 | `t=1` | 0.082 / 0.408 | 0.166 / 0.574 |
| 1 | `1−t_eps` | 0.079 / 0.372 | 0.113 / 0.526 |
| 2 | `t=1` | 0.106 / 0.513 | 0.102 / 0.442 |
| 2 | `1−t_eps` | 0.115 / 0.530 | 0.089 / 0.420 |
| 4 | `t=1` | 0.137–0.276 | 0.137–0.240 |

**结论**:细分不改善、4 反而更差 → 误差不来自离散化;端点取值确有缺陷(在 `t=1` 取值等于把残差除以 `t_eps`),截断到 `1−t_eps` 有效。

### 1.4 实验 A2:让反演成为"部署离散映射的逆"

按前向 Euler 的逐区间关系 `z_k = z_{k+1} − dt_k v(z_k,t_k)` 用阻尼 Picard 求解,初值取 Heun 结果。单条真实配对:

| 迭代 | 阻尼 | 节点残差 | 段残差 | 前向往返 L1 | 状态幅值 |
|---:|---:|---:|---:|---:|---:|
| 4 | 0.60 | 8.4e-4 | 2.6e-2 | 0.119 | 0.89 |
| 8 | 0.60 | 3.0e-3 | 2.8e-2 | 0.191 | 1.36 |
| 16 | 0.60 | 8.1e-3 | 4.0e-2 | 0.193 | 2.62 |
| 32 | 0.60 | 1.2e-2 | 7.0e-2 | 0.302 | 5.11 |
| 4 | 0.35 | 7.5e-4 | 2.6e-2 | 0.078 | 0.69 |

**结论**:Picard 在该场不收敛(`|1−dt·∂v/∂z|≥1`),迭代越多残差、误差、状态幅值同时变大。**残差只能表示求解精度,不能判定图像不可达**。因此该方案默认关闭(`inversion.solver=reverse_heun`),残差不再作为可达性判据。

### 1.5 实验 A3:严格重建门下,8000 条 I 候选能过多少

| 条件 | 通过 |
|---|---:|
| 源侧 L1 ≤ 0.08 | 1023 |
| 目标侧 L1 ≤ 0.08 | 289 |
| 目标侧 LPIPS ≤ 0.20 | 56 |
| 三项全过 | **17 / 8000(0.2%)** |

**结论**:目标图来自另一个生成器(用户用 Qwen 生成),不在本模型像集内,"要求本模型精确复现它"在构造上不可满足。**这不是数据脏,也不是代码缺陷。**

### 1.6 实验 A4:换成配对方向判据(暂缓)

`separation = L1(F(b),x_src) − L1(F(b),x_tgt)`,60 条样本:

- 60/60 条 `F(b)` 更接近目标而非源 → **方向正确**;
- 但 `L1(F(b),x_tgt)=0.179` 大于 `L1(x_src,x_tgt)=0.128` → **幅度越过目标**。

**结论**:I 标签是"方向对、幅度带噪"的弱监督,不能当 30% 权重的强监督。按用户决定,本轮**不做 I 的可用性重定义**,该判据默认关闭(`margin_fraction=0`)。

### 1.7 实验 A5:反演批次的图像证据

114 条 R-edit 记录,`hf(x_eff)` 对 `hf(x_src)`:

| 指标 | 值 |
|---|---:|
| `hf_before` 中位 | 0.093 |
| `hf_effective` 中位 | 0.281 |
| **比值 中位 / p90** | **2.55 / 4.48** |

人工判读(用户):啄木鸟、街道、客厅出现荧光色、彩边、大面积碎纹;卫生间加纸卷、加瓢虫等案例出现大幅重构。**结论:反演链在标签侧就已损坏画质,不能进训练。** 该批 114 + 87 条只作记录。

## 2. 被检验的替代路线:同噪声前向耦合

### 2.1 原理

不再"先有目标图再反演",而是用冻结原生流从**同一初始噪声**跑两条轨迹:

```text
a = F_{0→t}^{c_parent}(ε)
b = F_{0→t}^{c_prefix}(ε)          # 目标分支
x_eff = F_{t→1}^{c_tail}(b)
```

没有反演;`b` 与尾段共用同一数值路径。目标分支的前缀有三种取法,构成本轮 B 组实验。

### 2.2 配置公共项

`t=0.36`,50 步基础网格、shift=3、Euler、CFG=4、`t_eps=0.05`;`a`、`P`、`x_src` 一律**从缓存记录直接读取**(不重放),因此请求、预览、配对状态是同一场景。

### 2.3 实验 B1–B3:三种目标分支(同一 24 条请求)

| 路线 | 目标分支条件 | 通过 | `edit_complete` | `hf` 比值 p50 |
|---|---|---:|---:|---:|
| B1 纯文本 | `c_tail` 纯文本 | 9/24 | 12/24 | **1.11** |
| B2 教师读预览 `P` | IT2I(`P`+指令) 跑到 t,再 T2I `c_tail` | 6/24 | 15/24 | 2.00 |
| B3 教师读源图 | IT2I(源终图+指令) 跑到 t,再 T2I `c_tail` | 7/24 | **17/24** | 2.09 |

**结论**:图像条件确实提高"编辑做完"的比例(12→15→17),但**把纹理能量抬到约 2 倍**;通过率在 24 条样本内属噪声,不能判断优劣。

### 2.4 实验 B4:文本错配是不是原因

把教师与尾段改成**完全相同的字符串** `c_tail`(`--teacher-prompt target`),48 例:

| 指标 | 值 |
|---|---:|
| 通过 | 32/48(67%) |
| `edit_complete` | 39/48(81%) |
| `hf` 比值 中位 / p90 | **2.09 / 3.45** |

**结论**:与对照组(2.00 / 2.76)几乎相同 → **两个条件场的文本不一致不是纹理跳变的来源**。

### 2.5 实验 B5:交接本身是否加噪

同一批案例,比较"教师自己跑到底"与"教师跑到 t 再交给文本尾段":

| 案例 | `hf_src` | `hf_teacher`(教师跑完) | `hf_eff`(交接后) |
|---|---:|---:|---:|
| …16348 | 0.104 | 0.182 | 0.170 |
| …8649 | 0.068 | 0.198 | 0.169 |
| …6119 | 0.145 | 0.340 | 0.300 |
| …22562 | 0.141 | 0.514 | 0.483 |
| …15933 | 0.093 | 0.293 | 0.339 |

**结论**:两列接近 → **交接不加噪**;教师分支自身的样本就已经是高水平高频能量。

### 2.6 实验 B6:隔离"图像条件"本身(同文本、同噪声)

`A = T2I(c_tail)`、`B = IT2I(c_tail, 源图)`,同 seed、50 步、CFG=4:

| uid | `hf_text` | `hf_with_image` | 比值 |
|---|---:|---:|---:|
| …16348 | 0.095 | 0.184 | 1.94 |
| …8649 | 0.080 | 0.195 | 2.43 |
| …6119 | 0.104 | 0.333 | 3.20 |
| …200451 | 0.120 | 0.187 | 1.56 |
| …22562 | 0.143 | 0.512 | 3.57 |
| …15933 | 0.111 | 0.294 | 2.66 |
| …199228 | 0.088 | 0.183 | 2.09 |
| …21845 | 0.125 | 0.365 | 2.92 |
| …36541 | 0.123 | 0.367 | 2.98 |
| …7314 | 0.094 | 0.210 | 2.24 |

**中位 2.43×,范围 1.56–3.57。结论:图像条件采样本身让高频能量升到约 2.4 倍**,与"编辑加了内容"无关。(注意 `hf` 同时计入细节与噪声,"2.4 倍"不等于"2.4 倍伪影"。)

### 2.7 实验 B7:降低教师 CFG 能否把它拉回来

8 例,教师 CFG ∈ {1, 2, 4},其余不变,报 `hf_eff/hf_src` 中位:

| 教师 CFG | 比值 p50 |
|---:|---:|
| 1 | 2.48 |
| 2 | 2.04 |
| 4 | 2.07 |

**结论:CFG 不是旋钮。** 图像条件带来的高频上升不随 CFG 显著变化。

### 2.8 实验 B8:决定性对照——改进请求构造后,文本路线是否还需要教师

把**同一批 224 条 v5 请求**(第 3 节的构造)分别用两条路线跑:

| 路线 | n | 通过 | `edit_complete` | `hf` 比值 p50 |
|---|---:|---:|---:|---:|
| IT2I 教师读源图(v5) | 224 | 174(78%) | 200(89%) | 约 2.0 |
| **纯文本同噪声(同 224 条请求)** | 224 | **167(75%)** | **200(89%)** | **1.07** |

文本路线的拒绝原因:保留被破坏 32、编辑未完成 24、无可用保留题 1。

**两条路线的 `edit_complete` 完全相同(200/224),通过率只差 7 条(3%),而纹理能量差一倍。**

**结论:在"最小更新 TARGET + 1 条源图必假的编辑题 + 保留题来自源请求"这套构造下,纯文本路线与教师路线通过率相当、完成度略高,而纹理代价只有 1.07 对 2.0。教师不再有增益。**

## 3. 请求与判据的构造演进(为什么通过率从 25% 到 78%)

### 3.1 判据的三次修正

| 版本 | 判据 | 问题 |
|---|---|---|
| v2 | 目标侧绝对重建(L1≤0.08、LPIPS≤0.20) | 对 off-model 语料不可满足(17/8000) |
| v3a | `repaired≥1 且 lost==0`,参照预览诊断 | `lost` 实际是"仍失败",把"必须修好全部题"当通过,且放过"原来正确却被改坏" |
| v3b | 参照换成**实际被编辑的源图**,`Q_broken = Q_before_passed \ Q_after_passed` | — |
| **v4** | 语义验收搬到 **`x_eff`**;显式编辑要求 `edit_questions` 全过 + 源图至少未过一题 + `protected≥1` 且不破坏 | 本轮现行 |

### 3.2 请求侧的三处修正(效果最大)

| 修正 | 原理 | 效果 |
|---|---|---|
| TARGET 改为**最小更新** + `target_rewrite` 校验(与源描述内容词重合 <0.5 拒绝) | 自由改写会顺手加服装、动作、视角,等于换了任务 | 修掉"加纸卷变纸卷特写""加植物把航天飞机变电脑桌" |
| 编辑题压到 **1 条**,并强制**在源图上为假** | 源图已满足的要求不能定义"本轮变化" | `edit_not_needed` 从 77 条降到 0 |
| `preserve_questions` 改为**从源请求 `decompose` 后只取源图已通过者** | 模型自由写的保留题常与源描述无关,无法用于"破坏"判断 | `no_usable_preserve_questions` 从 11 条降到 0–1 |

### 3.3 通过率演进(同一路线、同一构造迭代)

| 迭代 | 合法请求 | 配对通过 | 通过率 |
|---|---:|---:|---:|
| 自由改写 + 多题(初版) | 32 | 12 | 37% |
| 最小 TARGET + 1 题 + 源图验证(48 条试点) | 29 | 22 | 76% |
| **同上,全量 400 条** | **224** | **174** | **78%** |

### 3.4 v5 全量数字

```text
候选提示词 400
→ 合法请求 224 (56%)
   拒绝: target_equals_request 65 | instruction_length 38 |
         edit_question_true_on_source 31 | target_length 17 | no_preserve_questions 13
→ 耦合配对 224
→ 可用 174 (78%)
   拒绝: preserve_broken 25 | edit_incomplete 24 | no_usable_preserve 1
   edit_complete 200/224 (89%) | protected≥1 223/224
```

## 4. 结论

1. **反演路线应当放弃**(作为标签来源)。它把求解器不匹配、端点处理与可达性混在一起;换成"部署映射的逆"也不收敛;在严格门下 8000 条只过 17 条;实测高频能量 2.55×。它仍可用于*诊断*(判断某图像是否在本模型流上)。
2. **图像条件教师不划算**。它确实提高编辑完成度,但代价是约 2 倍高频能量,且降低 CFG 无效;在改进后的请求构造下,纯文本路线的通过率与完成度都不低于它。
3. **当前应采用:同噪声纯文本耦合 + 三处请求侧约束 + 在 `x_eff` 上验收**。
   - 224 条请求全量:通过 **167(75%)**、`edit_complete` **200(89%)**、`protected≥1` 223/224;
   - 纹理代价 `hf` **1.07×**(教师路线 2.0×),与原生同源;
   - 每条配对成本约 25 s,224 条约 12 分钟(8 卡);
   - 与教师路线相比:完成度相同(200 对 200),通过率少 7 条,纹理代价只有一半。
4. **`x_eff` 的身份**要说清:它是"标签承诺的终图",不是训练路径中的中间态(训练只碰 `a`、`b`、`q_s`),也不是学生产出;学生产出是 `F(b̂)`,与 `x_eff` 的差就是学生状态误差被尾段放大后的结果。
5. **形体与纹理仍是独立人工项**。所有记录的 `effective_quality.pending_review` 均为 `true`;`hf` 只能提示"更硬/更糙",不能替代判读。

## 4b. 接口扫描:读取点与尾段步数(结论:对标签图无效)

### 目的

原本怀疑标签图的残留伪影来自接口(`t=0.36` 的读取点、8 段尾段)。用 8 个固定案例扫 `t ∈ {0.25, 0.36, 0.50}` 与尾段细分 `{1×, 2×}`。

### 结果

同一案例同一条件,`hf(x_eff)/hf(x_src)`:

| 读取点 `t` | 尾段细分 | 比值 |
|---:|---:|---:|
| 0.25 | 1× | 0.910 |
| 0.36 | 1× | 0.910 |
| 0.50 | 1× | 0.914 |
| 0.25 | 2× | 1.194 |
| 0.36 | 2× | 1.200 |
| 0.50 | 2× | 1.202 |

### 结论(比数字更重要)

1. **在纯文本耦合路线下,`x_eff` 与读取点无关。** 目标分支从头到尾都是同一噪声、同一条件 `c_tail` 的 Euler 积分,把中点从 0.25 挪到 0.50 只是把同一条轨迹重新分组;实测数值差异仅来自浮点重结合(`hf_src` 0.10418495535850525 与 0.10384726524353027,后者是末步顺序不同)。
2. 因此"换读取点让标签图更好看"在这条路线上**不可能成立**。读取点只改变 `a`/`b` 停在哪里(影响学生的学习难度与尾段长度),不改变标签图。
3. **尾段细分 2 倍让 `hf` 上升约 30%**(0.91 → 1.20),即"多跑几步"不会更干净;现有 8 段尾段本来就是较低高频的那一档,没有改进余地。
4. 推论:**文本路线的标签图就是该底座在 `c_tail` 下的原生样本**。它有没有伪影,等价于"这个底座在这条提示词下生成得好不好",与我们的接口无关;能改的只有提示词本身(或底座的 CFG/步数配置),不是读取点。

## 4c. 训练数据闸门(标签 → 训练之前的最后一步校验)

`scripts/build_training_cache.py` 把两条产线按**角色白名单**并成一个训练缓存,`scripts/verify_training_data.py` 用真实运行时把它读一遍(协议必须一致)。

```
{"linear": null, "native": 5003, "roles": {"R_edit": 167, "R_keep": 4836},
 "weights": {"R_edit": 0.15, "R_keep": 0.85}}
抽样 6 次: a/b/preview [1,3,512,512]、valid [1,1,512,512]、finite=true、
         R_keep 的 |b−a| = 0.0(符合 b=a 的定义)
```

两处必须记住的安全细节:

1. 第一次合并时**误把旧反演路线的 114 条 R_edit 也并了进来**(只按 role 过滤不够,因为 r_v3 里 R_edit 与 R_keep 并存)。改为**按缓存分别指定白名单**(`--allow <cache>=R_edit`)后,只剩耦合路线的 167 条;
2. `role_weights` 的校验原本强制 stage 2 必须包含 `I_edit`,现改为必须包含 L / R-edit / R-keep,`I_edit` 允许为 0。
