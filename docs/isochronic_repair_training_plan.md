# 从"编辑"到"纠错"：下一阶段训练安排

日期：2026-11-09。前置结论见 [等时状态训练方案](isochronic_terminal_training_plan.md) §13。

## 0. 目标

训练结束后要能跑通这条闭环，并且成图质量与最新 `x_eff` 对齐：

```text
原提示词
  → 原生 T2I 生成到 t=0.36，保存 a，取预览 P
  → UND 审查（对着 P 和原提示词）：
        判断哪里违反了原提示词，给出**一条**修正指令 e 与目标描述 c_tail
  → 状态转移 T_θ(a, P, e, c_tail)        ← 本轮训练的对象
  → 原生尾段接续到 t=1                  ← 冻结，不训练
  → 成图
```

"对齐质量"的操作定义：闭环 64 例上 `hf(x_eff)/hf(x_src)` 中位 **≤1.15**、**0–2 例**超过 1.5（当前图册是 1.08 / 0 例）。

**不是**继续证明能加多少种盆栽，也不是继续压 hf。

## 1. 为什么必须先改数据：现有池子没有修复样本

实测：

| 来源 | 数量 |
|---|---:|
| `r_v3` 父轨迹 | 5,117 |
| ├ 诊断通过 | 4,485（87.6%） |
| ├ `needs_edit` | **262（5.1%）** |
| └ `unactionable` | 370 |
| `explicit_v6` 请求 | 423，其中 **416 条是 Add（98.3%）**，0 条删除/计数/空间 |

也就是说：**模型没有被教过任何一次"撤销已有结构"**。真实失败率只有 5%，靠自然失败攒 1,500 条需要 3 万条轨迹——不可行。

结论：修复数据必须**构造**，不能等。

## 2. 数据方案（全量使用）

> 底座的具体构建（归一化、几何门禁、反向对冲、caption 生成）见 [数据底座构建方案](isochronic_data_build_plan.md)。

### 2.1 三源与配额

| 角色 | 占比 | 数量 | 来源 |
|---|---:|---:|---|
| L-edit（全量） | 40% | **28,849**（全用） | 现有高质量编辑对 |
| **R-repair（新）** | **45%** | **1,500** | 本轮生产 |
| R-keep（全量） | 15% | **6,576**（全用） | 现有真实轨迹保持记录 |

R-repair 按四类等量配额（各 ~375）：

| 类别 | 构造方式 | 难度 |
|---|---|---|
| 计数 | 提示词写死 "exactly N X"（N≥5），T2I 常画少/画多；UND 数完后给 ±k 修正 | 中 |
| 删除 | 提示词里没有的物体被画出来；UND 指出并移除 | 中 |
| 属性绑定 | 两个对象的颜色/材质被画反；UND 指出"红色应属于 A 不是 B" | 难 |
| 空间关系 | left/right、above/below 画反；UND 指出并交换 | 最难 |

**分两批**：先做计数 + 删除（A 批，750 条），跑一轮看信号；再做属性 + 空间（B 批，750 条）。理由见 §6 风险。

### 2.2 生产链路（复用现有脚本，只换请求生成）

```text
定向提示词池（约 4,000 条，四类各 1,000）
  → 原生 T2I 跑满 50 步：得到 a(t=0.36)、预览 P、父图完稿 x_src
  → UND 审查：对着 (原提示词, P) 判断，输出「失败的具体要求 + 一条修正指令 + c_tail + 两组问题」
  → 前置校验：这条要求在 x_src 上确实为假（否则丢弃）
  → 图像条件教师：从同一噪声在 (P, e) 条件下跑到 t=0.36 得 b
  → 部署尾段 x_eff = Φ^{c_tail}_{1←t}(b)
  → 验收：edit_questions 全过 + preserve 不破 + 质量可用
  → 入库
```

**关键一条**：训练时的修复指令必须由**与部署时相同的 UND 调用**产生，不能手写。否则训练/部署指令分布不一致，闭环一上线就掉点。

预计产出：4,000 条提示词 × 工程化失败率 40–60% × 配对通过率 ~70% ≈ **1,100–1,700 条**，取 1,500。

## 4. 训练配方

| 项 | 值 | 依据 |
|---|---|---|
| 损失 | 终端监督（结构 / 保持 / 高频带） | 已实现并验证 |
| 初始化 | `m64_terminal_lr2e5`（以 16:23 探针为准；若 hf >1.3 则退回 `step_003607`） | 已带终端监督行为 |
| `t` | 0.36 | 已证明读取点不影响标签图 |
| 编辑步数 | 8；尾段细分 1×，CFG=4 | 2× 更糙 |
| lr | 1e-5 → 2e-6 cosine，warmup 100 | 2e-5 使 hf 到 1.12，5e-6 只到 1.05；取中间 |
| 更新数 | **1,200 步**（64 卡） | 见曝光核算 |
| 保存 | 每 100 步，另存 150/300 早期点 | 修复能力可能前中期最好 |

**曝光核算**（1,200 × 64 = 76,800 样本）：

| 角色 | 权重 | 样本 | 每对曝光 |
|---|---:|---:|---:|
| L-edit | 0.40 | 30,720 | 1.06 |
| R-repair | 0.45 | 34,560 | **23.0** ≤25 ✓ |
| R-keep | 0.15 | 11,520 | 1.75 |

**成本**：终端监督 31 s/步 → **1,200 步 ≈ 10.3 小时**；加启动与评测约 11.5 小时。数据生产约 1 小时（64 卡）。

## 5. 门禁与判停

每 100 步在固定集上出图，五项：

| 指标 | 判据 | 说明 |
|---|---|---|
| `hf(x_eff)/hf(x_src)` 中位 | **≤1.15**，硬失败 >1.5 | 与最新 x_eff 对齐 |
| 原提示词复检通过率（闭环 64 例） | ≥ 基线 +20 点 | **主指标** |
| 未要求项破坏率 | ≤5% | |
| 4-way 诊断（见 §7） | 四形态的修正指令两两不同 | UND 是否在判断 |
| R-keep 的 hf | ≤1.10 | 保持任务不许变糙 |

任一项不过就停在该检查点并写原因，不硬推。

## 6. 分两批的风险管理

属性绑定与空间交换要求**重新组织已有内容**，这是当前完全没被训练过的能力，第一批很可能失败。所以：

- **A 批（计数 + 删除）先跑 200 步**：只验证"撤销已有结构"这件事能不能学。若 200 步内闭环修复率不动，说明读点 0.36 或 8 步不够重新组织结构，先回头调这两个，不要继续堆数据。
- **A 批有效再扩 B 批**：属性与空间。

这不是保守，是把"最贵的失败"放在最便宜的阶段。

## 7. 4-way 诊断集（验证 UND 真的在做判断）

同一句原提示词、四种画面，看 UND 是否给出四种不同动作：

| 画面 | 应有动作 |
|---|---|
| 只有 6 个牛角包 | 增加一个 |
| 有 8 个 | 删除一个 |
| 数量对但一个变红 | 只改颜色 |
| 全部正确 | 不动 |

12 例即可，**纯推理、不需训练**，可以在生产数据的同时先跑。这是"UND 从提供条件升级为决定修改"最便宜的证据。

## 9. 消融（各 150 步）

1. **不做 UND 审查**：直接拿原提示词当条件（无修正指令）——验证 UND 判断的贡献，这是论文主张的核心对照。
2. **只用 Add 数据**（v6 的 423 条）——验证修复数据的必要性。
3. **去掉高频带**（`frequency_weight=0`）——确认画质对齐不是靠这一项撑着的。

## 10. 验收交付

- 闭环 64 例图册：`x_src` / `step_003607` 编辑输出 / 当前编辑输出 三列
- 原提示词复检的逐题通过与失败
- 4-way 诊断的指令表（同一提示词四种动作）
- `hf` 与破坏率的逐例数据

**论文主张的落点**：理解专家让生成模型能够根据自身当前的错误，选择并执行不同的状态修改，在一次生成过程中恢复原始意图。判据是**原提示词不变、错误形式改变时，行为是否跟着变**——不是"是否比教师干净"。
